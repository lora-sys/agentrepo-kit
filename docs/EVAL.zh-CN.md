# Eval 运行与失败回归指南

## 两类评估不能混用

**确定性评估** 检查脚手架自身是否正确创建文件、保护用户内容、识别过期文档、传播失败状态、生成可验证 HTML。这些检查不需要模型。

**真实 Agent 评估** 需要指定模型、任务、仓库起始提交、预算和独立验收规则。必须执行同任务、同预算的配对实验，记录模型实际输入输出 Token，才能计算成功率差异和 Token 减少率。

## 本地基础检查

```sh
npm test
npm run eval:smoke
npm run check
```

## 真实仓库定位基准

准备合法取得的 noVNC、nvm、npm CLI 源码快照，统一放入一个目录。然后执行：

```sh
node benchmarks/run.mjs --projects-dir /path/to/source-snapshots --output reports/bench-local.json
```

每次评估应保留快照版本、来源、SHA256 和评估样例。不得将第三方项目源码直接打入本项目发布包。固定的少量代码定位题不能代表真实 Coding Agent 的完整任务成功率。

## 错误如何进入永久 Eval

1. 记录真实失败现象和最小复现条件。
2. 为确定性错误添加一个最小复现测试，先验证旧实现确实失败。
3. 修改实现，然后重新运行新测试和已有回归集。
4. 将故障编号、根因、测试文件和修复版本记录在 `eval/incidents.json` 或项目对应的故障记录中。
5. 在后续发布前重复执行，防止旧问题再次出现。

注意这里的 `eval/incidents.json` 指初始化后目标仓库拥有的文件。AgentRepo Kit 自身目前使用 `tests/` 和 `reports/` 保存其回归证据。

## 数据指标的定义

- `Top 1 / Top 3`：正确源码路径是否出现在排名前 1 / 3 名。
- `任务成功率`：是否通过独立、预先定义的功能验收。
- `准确率`：根据明确标签和统计口径计算，不能把目录检索命中称为开发准确率。
- `Token 减少率`：`1 - 优化组实际 Token / 基线组实际 Token`，仅对有效成对运行统计。
- `跳过`：没有安装或配置的检查必须单独计数，不算通过。

`eval dream` 是确定性流程模拟，**不是模型睡眠、学习或真实自主编程实验**。
