# AgentRepo Kit 第五轮 Eval 结果

日期：2026-11-15。源码版本：0.5.0。运行环境：Node.js v22.16.0，npm 10.9.2，Linux。使用离线执行；无真实大模型调用；未安装真实 dependency-cruiser 二进制。

## 实验范围

1. 空目录初始化和重复初始化，验证缺失文件创建、已有文件保留、安全路径约束和生成的 CLI 运行。
2. noVNC 1.5.0、nvm 0.40.3、npm CLI 10.9.2 三个已有代码仓库的本地源码快照。每个项目在独立临时目录中接入脚手架，检查原始文件 SHA256 不变、重复接入不覆盖、doctor、文档和回归检查。
3. 手工标注的 30 道代码定位题。其中 18 道开发题用于调试排序，12 道保留题用于独立检查。真值是固定源码路径，而不是任务补丁。
4. 14 个带有明确标签的故障检测样例、6 组隔离场景回归和 11 个确定性模拟开发步骤。
5. 从本地生成的 npm tarball 离线安装到独立前缀，再调用符号链接 CLI 初始化空项目。

## 统计口径

代码定位 Top 1 和 Top 3 使用预测文件路径和预先标注的期望路径作精确比较。基线使用同一个 CLI 的文件名模式；增强模式使用文件名、路径、有限源码关键词和任务主体短语排序。它们是规则程序，不调用语义模型。

已知故障诊断集标签直接来自合成夹具，得到 TP 7、TN 7、FP 0、FN 0，因此在这个小型固定集合上的诊断准确率、精确率、召回率都是 100%。不能据此断言在任意仓库上的误报率和漏报率都是 0。

全量文件路径清单平均 6931 字节；当前 `AGENTS.md` 加 Top 3 路径的定向上下文平均 1090 字节，字节量差为 84.3%。两种数据的语义内容不同，且不包含源码正文，属于上下文构造代理指标，不是实际 Token 减少率。真实 Token 还没有测量。

## 失败如何变成回归集

### AR-006：npm CLI 文档假阳性

v0.4 将 npm CLI 的网站路由 `[Install](/commands/npm-install)` 按仓库本地相对路径处理，文档检查失败。根因是链接检查遍历了整个 `docs/` 目录，而原项目有自己的文档发布语义。

v0.5 将检查范围缩小到工具管理的文档、`docs/domains/`、`docs/decisions/`、`docs/plans/` 和显式声明的文档规则。根路径网站路由跳过本地文件校验，但相对路径失效仍然被捕获。回归记录：`eval/scenarios.json` 中的 `site-routes-preserved` 和 `broken-managed-link`。

### AR-007：npm 安装后命令静默退出

源码测试使用 `node bin/agentrepo.mjs`，没有覆盖 npm `.bin/agentrepo` 符号链接路径。启动逻辑使用了原始路径字符串精确比较，导致 npm 安装后没有执行 CLI 主入口。

v0.5 使用真实路径比较，并新增 `tests/install-entry.test.mjs`。将包通过 `npm pack` 打包并用 `npm install --offline` 安装到临时前缀后，已经验证 `agentrepo version`、`agentrepo init` 和项目内 Eval 命令正常执行。

### AR-008：架构规则发生变化时没有同步生成配置

初始化架构配置后，修改 `agentrepo.json` 中的模块约束不会自动更新 `.dependency-cruiser.json`。v0.5 增加 `arch sync` 和托管文件哈希。配置与规则不一致时，严格检查失败。检测到用户手工编辑生成文件时，拒绝覆盖。回归记录：`tests/architecture-sync.test.mjs`。

### AR-009：代码定位词形差异影响命中

`execute` 与 `exec`、`handling` 与 `handler` 过去被视为不同词。v0.5 增加少量可审计的词形归一化和任务前部短语优先级，在开发题上进行调整并复查保留题。没有用模型权重或人工标注补丁直接回答定位题。

## dependency-cruiser 状态

已实现：生成配置、禁止循环依赖、未解析依赖告警、自定义层间导入禁止规则、`arch sync` 托管配置同步、实际 CLI 调用约定、错误退出码传递、缺少依赖时严格失败和隔离测试。

未完成：npm Registry 在当前环境不可达，没有下载并运行官方 dependency-cruiser。针对 mock 可执行文件验证的接线不等于工具内部实际检测能力。下一轮必须在可访问 npm Registry 的 CI 中安装依赖，运行包含循环引用和禁止层间导入的真实 JS/TS 样例。

## 模拟开发的性质

`eval dream` 在临时目录创建错误的加法函数及独立单元测试，确认测试失败后修改实现，确认测试通过，检测源文件索引失效，更新索引，重跑回归并写入交接状态。总共 11 阶段。这是可执行的状态机实验，不是自动调用智能体训练模型，也没有宣称模拟生成的 Token 计数就是实际 Token 使用。

## 可复现文件

`reports/bench-v5.json` 保存 30 题预测、排名、源码版本和 SHA256。
`reports/audit-v5.json` 保存故障标签及混淆矩阵。
`reports/dream-v5.json` 保存 11 阶段模拟轨迹。
`reports/tests-v5.txt` 保存 35 项 Node 自动测试结果。
`reports/pack-manifest.json` 保存 npm 打包清单。
`reports/install-v5.json` 和 `reports/install-scenarios-v5.json` 保存离线安装后的真实 CLI 验证。

本报告不提供没有测量依据的真实 Agent 成功率、实际 Token 减少率或跨项目泛化率。
